After a model upgrade, should rules be removed or retained?
Participant A suggested removing unused skills and comparing execution traces on the same task. Another participant argued that engineering still needs constraints. The discussion then turned to cheaper models and explicitly selecting subagent models.

2026-09-18

Why call an agent at every step of a stable workflow?
After visiting businesses, participant A reported that some users preferred fixed scripts and questioned ongoing token use; other customers wanted every task replaced by an agent. Replies proposed agents for open-ended problems and exceptions. Another participant recommended code for explicit rules, agent nodes for exception-heavy steps, and moving discovered stable rules back into code. A welcomed the approach.
This is a design discussion with self-reported customer visits. Declining model-call share with maturity remains a recommendation without longitudinal statistics. Autonomy is not a direct measure of maturity.

Human–agent collaboration that month (industry-wide)

People are beginning to coordinate multiple agents, yet practice reports still require humans to check annual-report page numbers, correct row references and detect business-level API failures behind successful HTTP responses. Some delegate judgment while others strengthen acceptance checks; a causal link from attention demands to surrendered judgment remains unproven.

Multi-agent division of work and continuously running harnesses are entering practice, alongside reports of idle loops, false passes and failed verification. L1 observes, L2 advises, L3 requires approval for each execution, and L4 executes autonomously, classified per action. Permissions, budgets, stopping rules and independent checks jointly define the boundary.
