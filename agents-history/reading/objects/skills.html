升级模型后，规则应该删还是留？
参与者 A 建议清理长期不用的 Skills，并用相同任务比较不同模型的执行轨迹。另一位参与者指出，工程任务仍需要规则约束，不能把旧规则一概删除。讨论随后转向成本：有人选择继续用较便宜的模型，也有人建议明确指定子代理的模型。
这段讨论没有得出统一配置。分歧在于：减少上下文负担与保留工程约束，哪一项在当前任务里更重要。

2026-09-18

稳定流程为什么还要每一步都调用 Agent？
参与者 A 走访企业后发现，有些使用者更倾向固定脚本，并关心持续消耗 Token 的必要性；同时，他也遇到希望每项工作都换成智能体的客户。讨论中有人建议把 Agent 用于开放问题和异常。另一位参与者进一步提出：规则明确的环节用代码，例外多的环节加入 Agent，探索后能够固定的规则再沉淀为代码。A 对这个方法表示认可。
这是带有客户走访自述的设计讨论。模型调用占比随成熟下降仍是建议，并没有纵向统计；但它提醒我们，自主程度不能直接当作成熟程度。
